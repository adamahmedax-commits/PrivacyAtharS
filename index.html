هذه مسودة أُعدت من مراجعة الشيفرة وليست اعتمادًا قانونيًا نهائيًا. تعتمد بعض التفاصيل، خصوصًا الاحتفاظ لدى مزوّدي الخدمة والنسخ الاحتياطي، على إعدادات حسابات وخدمات لا تظهر في ملفات المشروع.

لا يظهر في نسخة المشروع التي تمت مراجعتها تسجيل حساب مستخدم أو إنشاء ملف على خادم التطبيق. ولم تُعثر على SDK إعلانات أو تحليلات/تتبّع مدمج مثل Firebase Analytics أو Crashlytics أو Sentry أو Bugsnag. سجل النشاط والإحصاءات الذي يعرضه التطبيق يُنشأ ويُحفظ محليًا، ولا يظهر في الشيفرة مسار يرسله كأحداث تحليلات.

2. البيانات التي تُحفظ على الجهاز

قد يحفظ التطبيق محليًا، بحسب الميزات التي تستخدمها، إعدادات العرض والتفضيلات، اختيار القارئ وتخطيط القراءة، موضع/تقدم القراءة، الأذكار والعدادات، سجل النشاط والإحصاءات، العادات وأسمائها وأوصافها وأيام إنجازها وتذكيراتها، إعدادات ومواعيد الصلاة وموقعها المختار أو إحداثيات GPS، إعدادات الإشعارات، وتاريخ محادثات المساعد «أثري» ومحتواها.

تُحفظ هذه البيانات في تخزين التطبيق المحلي مثل WebView localStorage وAndroid SharedPreferences. يحتفظ سجل محادثات «أثري» بما يصل إلى 20 محادثة وبحد أقصى 80 رسالة لكل محادثة في الشيفرة. لا يظهر في المشروع تاريخ انتهاء تلقائي لهذه البيانات؛ وتبقى على الجهاز حتى حذفها من واجهة الميزة إن توفّر، أو مسح بيانات التطبيق/إزالته. يتضمن التطبيق خيارًا لتصفير سجل الإحصاءات، لكنه لا يصفّر جميع بيانات التطبيق.

يسمح AndroidManifest بالنسخ الاحتياطي للتطبيق (allowBackup=true)، وأكد الناشر أن الإعداد الحالي مقصود. لا تظهر قواعد استثناء مخصصة في ملفات المشروع. قد يعتمد تضمين بيانات التطبيق في نسخة احتياطية واستعادتها على إصدار Android وإعدادات جهاز المستخدم؛ ولا يحدد المشروع أي البيانات ستُضمّن فعليًا أو مدة الاحتفاظ بنسخة Android الاحتياطية.

3. البيانات التي تُرسل خارج الجهاز

  • الموقع لمواقيت الصلاة: عند اختيار موقع GPS، تُرسل إحداثيات خط العرض والطول وطريقة الحساب إلى واجهة AlAdhan لجلب المواقيت. وعند اختيار مدينة، تُرسل إحداثيات المدينة. يحفظ التطبيق اختيار الموقع/الإحداثيات محليًا أيضًا. ويحسب اتجاه القبلة من الموقع ومستشعر الاتجاه داخل التطبيق؛ لم يظهر إرسال خاص باتجاه القبلة إلى خادم.
  • اختيارات التلاوة: عند طلب التلاوة أو توقيت الآيات، يطلب التطبيق بيانات من Quran.com API باستخدام معرّف القارئ والسورة أو الآية. تُحمّل ملفات الصوت من مضيفين خارجيين بحسب القارئ ومصدر الملف، ومن أمثلتها MP3 Quran وQuranicAudio وQuran.com وArchive.org وAssabile. لذلك قد تكشف طلبات تلك الخدمات عنوان الشبكة والملف/التلاوة المطلوبة. الغرض الظاهر هو تشغيل المحتوى، وليس إرسال حدث تحليلات مستقل.
  • رسائل المساعد: عندما يرسل المستخدم رسالة إلى «أثري»، يرسل التطبيق نص الرسائل الأخيرة ذات الصلة إلى خادم Cloudflare Worker المعرّف في التطبيق، كي يعالجها Workers AI ويرجع الرد. لا يرسل التطبيق سجل فتح الصفحات أو ضغطات الأزرار لهذا الغرض.
  • الصوت للمساعد: عند استخدام التسجيل الصوتي، يسجل التطبيق الصوت بعد منح إذن الميكروفون، ثم يرسله إلى مسار تحويل الصوت في Cloudflare Worker ليحوّله Workers AI إلى نص. التسجيل لا يُرسل تلقائيًا عند تشغيل التطبيق؛ يلزم بدء ميزة التسجيل. يضع التطبيق الملف المؤقت في مجلد cache ويحذفه بعد قراءة الملف في المسار البرمجي الطبيعي. بعد التحويل يظهر النص للمستخدم، ولا يُرسل إلى المحادثة إلا عند إرساله كرسالة.
  • بيانات الاتصال التقنية: عند الاتصال بالخدمات الخارجية، تتلقى تلك الخدمات بيانات الاتصال اللازمة لطلبات الإنترنت، مثل عنوان IP وبيانات الطلب. يقرأ Worker عنوان IP الذي يوفره Cloudflare ويستخدمه مفتاحًا لتحديد معدل الطلبات، ولا يظهر استخدامه لتتبّع التصفح داخل التطبيق.
  • سجلات أخطاء الخادم: عند حدوث أخطاء من فئة الخادم، يسجل Worker وصف الخطأ عبر console.error. لا يظهر في استدعاء التسجيل إرسال سجل الصفحات أو ضغطات المستخدم، لكن محتوى الوصف قد يعتمد على الخطأ الذي أعادته الخدمة. لا يحدد المشروع مكان أو مدة الاحتفاظ بسجلات Cloudflare.

Privacy Policy for Athar

This policy describes how the Athar Android app handles data when its features are used. Publisher/data controller: Adam Farouk and Adam Ahmed. Privacy contact: sakurastudioone@gmail.com.

This is a code-based draft, not final legal approval. Some details, especially service-provider retention and Android backup behavior, depend on account and service settings that are not present in the project files.

1. Accounts, ads, and analytics

The reviewed project does not show user account registration or an app-owned server profile. No advertising or analytics/tracking SDK such as Firebase Analytics, Crashlytics, Sentry, or Bugsnag was found in the reviewed dependencies. The app's activity and statistics history is generated and stored locally; no code path was found that sends it as analytics events.

2. Data stored on the device

Depending on features used, Athar may store display preferences, reciter and reading settings, reading progress, adhkar and counters, activity/statistics history, habit names/descriptions/completion dates/reminders, prayer location/settings/schedules, notification settings, and Athri assistant conversation history and content.

This information is stored locally, including in WebView localStorage and Android SharedPreferences. The assistant history code permits up to 20 conversations and up to 80 messages per conversation. The project does not set an automatic expiry period for most local records. They remain until removed through a feature where available, or until app data is cleared/the app is uninstalled. The app includes a reset for the statistics history, but that does not clear all app data.

The Android manifest sets allowBackup=true, which the publisher confirmed is intentional. No custom backup-exclusion rules were found in the reviewed project. Whether app data is included in or restored from an Android backup may depend on the Android version and the user's device settings; the project does not define exactly what is included or how long Android backup copies are retained.

3. Data transmitted off the device

  • Location for prayer times: When GPS is selected, latitude, longitude, and the calculation method are sent to the AlAdhan API to retrieve prayer times. When a city is selected, that city's coordinates are sent. The app also stores the selected location/coordinates locally. Qibla direction is calculated on-device using location and device orientation; no separate transmission for Qibla direction was found.
  • Recitation selections: When a recitation or verse timing is requested, the app calls the Quran.com API with a reciter ID and surah or verse identifier. Audio files are delivered by external hosts depending on the reciter and source, including MP3 Quran, QuranicAudio, Quran.com, Archive.org, and Assabile. These services may therefore see the network address and requested recitation/file. The apparent purpose is content delivery, not a separate analytics event.
  • Assistant messages: When a user sends a message to Athri, the app sends recent relevant messages to the configured Cloudflare Worker so Workers AI can process the request and return a response. The app does not send page-opening or button-click logs for this purpose.
  • Assistant voice: If a user starts voice recording, the app records audio after microphone permission is granted and sends it to the Cloudflare Worker transcription endpoint for Workers AI transcription. Recording is not sent merely because the app launches; the recording feature must be started. The app writes a temporary file in its cache directory and deletes it after reading it on the normal code path. The transcript is shown to the user and is sent as a chat message only if the user submits it.
  • Connection metadata: When connecting to external services, those services receive information needed for internet requests, such as IP address and request metadata. The Worker reads the IP address supplied by Cloudflare as a rate-limit key; the reviewed code does not use it to track in-app browsing.
  • Server error logs: For server-class failures, the Worker writes an error description using console.error. The logging call does not show page or button-event logs, but the description may depend on the underlying service error. The project does not define where Cloudflare logs are stored or how long they are retained.

The data above is transmitted to provide the feature the user requested: prayer-time calculation, recitation content/playback, or processing an assistant question/recording. The Worker logs some server error descriptions for operations; the project does not specify their retention. Feature data is stored locally, but the code does not set a time-based deletion period for most device records. Users can reset the activity statistics from the statistics page; this does not remove counters, habits, or other app data. Local app data can be removed through Android app settings by clearing app data or uninstalling, subject to possible Android backup behavior.
